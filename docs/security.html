Security

Security

Security is a core design principle of World Tree. The project is built with layered protections, responsible disclosure practices, and a commitment to continuously improving its security posture.

Security Philosophy

World Tree follows a defense-in-depth approach. Authentication, authorization, configuration validation, and operational safeguards are designed to minimize risk while maintaining reliable functionality for Discord communities.

Current Security Features

The current platform includes:

  • Discord OAuth2 authentication with PKCE.
  • Encrypted and signed authentication sessions.
  • AES-256-GCM protected session payloads.
  • Strict environment configuration validation.
  • Clear service and repository boundaries.
  • Permission-based administrative controls.
  • Structured logging and operational safeguards.

Responsible Disclosure

If you discover a potential security vulnerability, please do not disclose it publicly through GitHub Issues, Discord, or social media.

Instead, follow the reporting process described in the repository's SECURITY.md .

High-Sensitivity Components

The following areas receive additional attention during development, testing, and review:

  • Authentication and OAuth flows.
  • Session management.
  • Permission and moderation systems.
  • No-prefix authorization.
  • Dashboard authentication.
  • External music process execution.
  • Configuration and environment handling.

Supported Versions

Security updates are provided for the latest actively maintained version of World Tree. Users are encouraged to keep deployments up to date to receive the latest fixes and improvements.

Security Best Practices

Server administrators should protect bot tokens, regularly update dependencies, restrict privileged permissions where appropriate, and avoid sharing configuration files containing sensitive credentials.

Response Process

Security reports are reviewed as quickly as possible. Confirmed vulnerabilities are investigated, prioritized based on severity, and addressed before public disclosure whenever practical.

Contact

For general support, visit the Support page. For security-related concerns, follow the responsible disclosure process described above.
